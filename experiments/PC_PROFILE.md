# Optional per-thread CPU instruction sampling

Experimental branch; selected submission source remains82d185b15affaf4b65fcb4936d23d410478debfc. Hardware perf_event_open user-only cycles failed with EPERM. This optional sampling feature is not in that selected source and compiles out when disabled.

Build with --features sampling and CARGO_PROFILE_RELEASE_DEBUG=1, keeping release optimization/LTO and debuginfo=1. Set SS_PC_SAMPLE=path.json and SS_PC_PHASE=parse to sample just the parsing barrier. Each worker has a targeted CLOCK_THREAD_CPUTIME_ID timer, nominal1ms; a process-wide timer could instead sample the idle leader. The SA_SIGINFO handler reads RIP from the Linux/x86-64 ucontext and increments preallocated lock-free atomic counters only. Timer delivery may coalesce and instruction attribution is quantized to16-byte bins; these are approximate PC frequencies, not cycle counters, call stacks or exact CPU milliseconds. Outside-executable samples are retained separately.

Five current-generator20M runs on the local2-CPU quota VM produced5,322 executable and437 outside-executable parse-phase samples. Both complete tables matched the frozen reference, and current1M matched the official answer. The debug binary is not checked in. Stage1 loop/input-load locations accounted for the largest concentrated sample group; exact-ID cache lookup and stream writes were smaller groups. This identifies candidates for further measurement, not proof of a memory-bandwidth limit. All samples, symbolization and coarse source-line distributions are retained locally; the aggregate is committed beside this note.
